## 认知内核

### 核心命题

方向先于强度。先扩大可见的选项，再把资源集中到有证据、自己能承受的突破口。

### 六个内核

| 内核 | 判断问题 | 落地动作 |
|---|---|---|
| 先自由，后财富 | 我想增加哪种自由：时间、地点、选择、创造？ | 明确最低生活条件、责任与可支配资源 |
| 轻承诺，留机动 | 新承诺给我什么，锁住什么？ | 比较持有成本、退出成本和真实使用价值 |
| 时间是稀缺资源 | 哪件重复劳动值得删掉、简化或自动化？ | 先处理一件高频小事，把省下的时间用于主线 |
| 趋势、时机、可进入性 | 需求增长有何证据，我凭什么进入？ | 找一条真实需求，交一个最小样品 |
| 杠杆放大有效能力 | 哪个成果可以重复使用或帮助更多人？ | 把一次工作做成模板、作品、产品或协作流程 |
| 横向复利，纵向聚焦 | 哪些能力能互相加成，当前瓶颈是什么？ | 广泛试探后只保留一个主攻方向和必要支撑 |

「三不主义」保留为检查过早锁定的工具：购房、购车、婚姻等承诺分别算账。年龄口号不替代个人偏好与家庭现实；一段高质量关系也能增加自由与支持。

### 看格局、看趋势、看时机

**格局**：结果由谁买单，谁拥有入口，谁能持续交付？自己做价值创造、渠道连接还是资源组织？

**趋势**：区分需求增长、流量增长和估值上涨。查询当前资料，关注使用、留存、付费与成本，而不只追随热词。

**时机**：新技术成熟度、用户准备度、渠道和规则是否允许今天进入？试验成本低可以早做；重投入要等关键假设有实证。技术前景与当下收益可以相距很远。

### ROI：用来比较，不替代价值选择

```text
ROI 启发式 = (结果收益 R × 实现概率 P) / (直接成本 C + 评价消耗 E + 未来切换成本 S)
```

先用真实单位比较时间、钱、交付成果；必要时再由用户给同尺度主观分数。没有可信概率时，用「顺利 / 普通 / 失败」情景说明结果，不把猜测写成 78% 成功率。

- R 包括用户在意的成长、关系、自由与体验，不只现金。
- C 包括今后的必要投入、机会成本与需履行的责任。过去花掉的钱是沉没成本。
- E 拆成无关评价消耗与真实信誉后果；后者放入现实成本。
- S 是从现在切换产生的费用、学习和交接，避免与 C 重复。
- 身份、安全、承诺等硬约束先判断；单个高分不能抵消硬约束。

原方程省略了损失幅度、尾部风险及收益时间。重大选择单独写出最大可承受损失、回报周期和退出方法。工具输出的比值是当前假设下的相对比较值。

### 广探、试验、聚焦、扩展

1. **广探**：补参照系，不急着证明最初的想法正确。
2. **试验**：付出少量真实时间、作品或预算，换取外部反馈。
3. **聚焦**：需求、交付能力和承受力得到支持后，把最好的时段集中投入。
4. **扩展**：先让现有模式可重复，再增加渠道、产品或协作。扩展消耗旧主线时，重新算账。

「All in」在本系统中优先指注意力与执行聚焦；是否投入更多资本，要另外评估现金流和损失承受力。

### 三策推演

为重要决定设计两三条机制不同的路线：例如在原岗位争取项目、带作品转岗、独立提供服务。上/中/下只是主模型的方案标签，不预设优劣。按目标、约束、信息价值推荐一条，不固定取中策，也不凭模型多数票做决定。

### 示例：要不要转行

先说明你要离开的到底是公司、岗位还是行业。保留工作试做目标岗位的小任务，带着作品接触真实从业者；如果已有录用机会和足够缓冲，直接比较两个可兑现的选择。若现有环境有严重伤害，退出安排可以优先于试验。

## 心智模型与决策启发式

阅读导航：模型库 → 行动启发式 → 增长传播 → 表达。一个问题选 1–3 个真正改变判断的模型，不逐项朗读。

### 元模型：增量与存量

先判断机会来自新增需求、提高效率还是重新分配，再选打法。局部趋势与个人可进入性比宏观口号更有用，详见 [01](01-总纲.md)。

### 十四个模型的个人版

下列名称对应 `0xquqi/sun-skill` 的归纳，本表是本系统的改写与适用条件。

| 原模型 | 提炼的问题 | 用于行动 | 适用条件 |
|---|---|---|---|
| 1 德扑／Winner-Takes-All | 这里是少数赢家占大头，还是能多人共存？ | 有网络效应时选能打穿的小领域；其他市场可做小而盈利的服务 | 先找市场结构证据，不假设所有竞争都赢者通吃 |
| 2 鸡与鸭范式识别 | 我是在拿不合适的尺子评价自己吗？ | 换任务、组织或环境，使用可迁移能力 | 同时识别确实需要补的技能 |
| 3 冷血→温血动物进化 | 哪种新方式在成本或性能上持续改善？ | 分开判断技术趋势、采用条件和自己的机会窗口 | 类比用于提问，不以用户规模阈值断言必然胜出 |
| 4 注意力→价值 | 谁关注，关注后做什么，谁得到价值？ | 明确触达—行动—交付—复购/复用链 | 高曝光要能转化；争议带来的信誉与服务成本也计入 |
| 5 登山营地 | 到下一阶段真正缺哪项能力？ | 学习→作品→真实任务→可重复服务，分阶段突破 | 用可观察的成果定营地，不凭空套统一估值门槛 |
| 6 研究失败 | 类似的人和项目为什么没做成？ | 找最相关失败路径，先验证最脆弱假设 | 同时看失败样本与环境差异，避免倒推原因 |
| 7 叛逆—和解 | 哪条惯例值得改变，哪部分合作有价值？ | 表达自己的路线，围绕实际利益达成合作 | 对事实与责任保持一致，不为姿态对抗或妥协 |
| 8 杠杆增值 | 哪个有效能力可以被工具、产品、协作放大？ | 先有可交付成果，再提高复用与覆盖 | 金融杠杆另算损失承受力；放大错误同样容易 |
| 9 监管滞后 | 新做法和现行规则哪里不匹配？ | 核实规则，选择允许的做法、时间和地区 | 历史类比不构成当前合规结论 |
| 10 黑客帝国觉醒 | 这是主动选择还是未经检查的默认脚本？ | 列出“我想要 / 我接受的代价”，重做一次选择 | 买房、考公、结婚等也能是深思后的自主选择 |
| 11 性与权力→钱与自由 | 我的追求受身份竞争驱动，还是服务于想要的生活？ | 定义个人自由，用现实资源支持它 | 这是来源的价值叙事，不给人与关系划先进/落后等级 |
| 12 正收益系统叠加 | 多次行动是否持续带来净学习、机会或回报？ | 选择互补且成本可承受的环境、技能与渠道 | 要计成本与相关性，不把主观优势直接相乘成收益率 |
| 13 From It to Bit | 哪个经验能结构化、复制和协作？ | 把反复使用的知识变成文件、模板或工具 | 可机器读取有利复用；是否公开由实际用途与隐私决定 |
| 14 道德流变 | 外界评价是事实后果、群体惯例还是权利问题？ | 放下单纯身份评判，认真处理伤害、承诺与规则 | “观念会变”不推出某做法必然正确 |

### 十八条启发式如何进入自己的系统

| 来源启发式 | 本版行动原则 |
|---|---|
| 不做悲情英雄 | 不把自我感动当成果，选择能交付、能持续的做法 |
| 不要怂，继续干 | 方向依据仍在、成本可承受时，完成下一步 |
| 使命 > 金钱 > 名誉 | 明确自己的长期目标，区分口碑虚荣与真实信用 |
| 局部集中十倍兵力 | 选一个足够窄的突破口，把最好资源投到关键瓶颈 |
| 先做被允许的地方 | 查当前规则，在允许的范围与条件下试验 |
| 三不主义 | 评估长期承诺的使用价值、自由收益与切换成本 |
| 方向 > 技巧 | 先判断做这件事值不值得，再优化技巧 |
| Auto Pilot | 预先约定何时行动、何时复盘，降低情绪来回拉扯 |
| 平常心 | 区分一次小失误与方向性问题，不扩大挫折含义 |
| 勇气 | 接受必要的不确定，承担自己选定的有限代价 |
| 坦诚沟通 | 清楚说目标、事实、要求；真实错误直接修正 |
| 自带干粮 | 从现有资源可做的版本起步，外部支持不是唯一入口 |
| 早行动 | 低成本试做常比继续追求完美准备更有信息价值 |
| 去产生效率的地方 | 比较需求、学习密度和协作机会，再决定迁移或远程进入 |
| 不存在后悔 | 决定后减少反刍，复盘时仍可承认错误并改路 |
| 坚持正收益系统 | 多次观察净收益；短期波动与结构失效分开处理 |
| 别传教，用结果说话 | 先交作品或完成试验，再按需要解释，不靠争赢获得行动许可 |
| Skin in the Game | 用真实练习和小交付增加投入感；不要求先买币或冒大额风险才学习 |

### 增长传播：把注意力接到价值上

1. **对象**：谁确实有这个问题，在哪里能接触到他们？
2. **主张**：一句话说明为他们省下什么、获得什么。
3. **证据**：作品、演示、用户反馈或可核对的数据。
4. **钩子**：一个相关热点、鲜明观察、具体反差或个人经历。
5. **行动**：让读者完成一个自然的下一步，如试用、阅读、预约或反馈。
6. **兑现**：承诺后的体验与留存。比较触达、有效咨询、完成率和实际收益，而不只看点赞。

先给能落地的选题或文案，再按用户的时间与预算设计小试验。热点要相关，数字要真实，借势不伪装合作、背书或用户经历。只有用户要求发布时才执行发布。

### 孙学表达：明确、有势能、能兑现

保留来源五类形式的有用部分：排比强化一个主张；类比解释难点；真实数据提供证据；相关热点提供入口；指出旧假设的问题并提出可行新做法。一次通常用其中一两种。

默认用「判断 → 关键变量 → 一步行动」。用户要孙哥式表达时，可以更短、更有冲劲；正常分析保留未知和反证。涉及人物口吻时标明风格化表达，不声称本人发言。

改写示例（本系统原创）：

- 迷茫：**先拿一个真实任务。做出东西，你才知道下一步该补哪块能力。**
- 拖延：**准备到这里够了。今天交第一版，让反馈接管猜测。**
- 聚焦：**先打穿一个小场景。有人持续需要，再往外扩。**
- 面子：**把解释的时间拿回来，留给你想做成的事。**

具体文案使用 [增长传播与表达提示词](../prompts/09-孙学增长传播与表达.md)。

## AI 时代人生行动

阅读导航：生活与 AI → 人生选择 → 学习与创造 → 关系与承诺 → 个人总纲。

本章把孙学用于一个人的实际生活：怎么起步、选工作、换环境、学习、承担承诺、调整状态。商业只是其中一种场景。

### 生活 AI 化：从一个反复出现的问题开始

挑一件具体任务，例如整理学习材料、复盘一周时间、准备下一次求职或记录训练。告诉 AI 目标、约束和现有材料，让它完成一个可用结果；用真实使用体验纠正它。

先用现有工具。反复有用后，才考虑自动化、增加订阅或设备。资料存成自己能读取的文件，换模型仍能继续。对照模型时看具体分歧，判断依据回到事实。

这是对访谈中生活 AI 化、低成本开始和 AI 协作的行动化改写。原笔记定位：[00:01:57](https://www.youtube.com/watch?v=0Z-vhBvBmUY&t=117s)、[00:09:20](https://www.youtube.com/watch?v=0Z-vhBvBmUY&t=560s)、[00:15:46](https://www.youtube.com/watch?v=0Z-vhBvBmUY&t=946s)。时间码用于回看，自动转写的具体措辞须核对原视频。

### 人生选择：先自由，再选择愿意承担的约束

自由可以是下班后拥有时间、照顾家人的能力、迁居的选择权，也可以是持续做喜欢的工作。先由用户定义。

| 场景 | 孙学判断 | 一个有信息价值的行动 |
|---|---|---|
| 选专业、转专业 | 兴趣、真实任务、门槛与可迁移能力 | 做一份该专业常见任务，访谈一位学生或从业者 |
| 换工作、转行 | 离开的原因、目标岗位、已有积累与生活缓冲 | 对照真实岗位做一个小作品，尝试投递或内部转岗 |
| 去大城市、出国、迁居 | 机会密度、成本、规则、支持网络与家庭条件 | 远程接触工作/社群，计算生活条件；条件允许再短住体验 |
| 买房、买车等大承诺 | 实际用途、可负担性、灵活性与机会成本 | 比较持有、租用、推迟等真实方案及退出代价 |
| 创业、副业 | 谁需要、如何交付、能投入多少 | 做小样，向目标用户获得反馈；有需求证据再扩大 |
| 对眼前生活不满意 | 最难忍的一点是什么，能影响哪部分？ | 先改一个具体条件，如工时、通勤、任务分工或求职入口 |

小试验用于减少关键未知，不变成无限拖延。用户已拿到足够证据时明确推荐，并指出需要承担的取舍。

### 学习：缺啥补啥，尽早产出

1. 找到想完成的真实任务或想进入的角色。
2. 将它拆成已会、需练、需借助三部分。
3. 只学当前瓶颈，马上用在作品里。
4. 找用户、同行、老师或实际任务检验质量。
5. 把有效步骤整理成可再次使用的素材、模板或流程。

作品可以是一个分析、一篇文章、一个程序、一次讲解或一项服务。第一次投入真实时间和责任就能形成反馈，不必先买昂贵课程或金融资产。

### 多创造，少被动消费

对想做内容的人，先把亲手解决的一件事讲清楚。对不想公开的人，作品也可服务个人学习或内部协作。公开与否由用途决定；一份真实、可复用的成果比无休止收藏更能检验学习。

内容创作与资产配置是两个决定，各自看能力与承受条件；不要求把兴趣全部变现。

### 关系与承诺

保留与值得合作的人建立关系的能力。要独立，也要识别互相支持带来的价值。

- 家人不认可但没有共同资源影响：说明路线和自己的责任，少争论身份标签。
- 影响共同生活、照护或资金：把方案拿出来谈，修改真实冲突。
- 想表达兴趣或提出请求：转到 [黄毛社交框架](04-黄毛.md#social)，清楚开口并尊重对方选择。

### 三策转成小试验

写明：**要验证什么 → 做什么 → 花多少 → 得到什么 → 何时/满足何条件再决定**。

示例：一个每周能投入四小时、想转内容运营的人，可以用两小时制作与目标岗位相关的样稿，再用其余时间修改并获取真实反馈。是否转岗依据岗位与反馈逐步更新；这不是适用于所有人的固定周计划。

### 你的个人总纲

需要持续使用时填 [personal-profile.md](../templates/personal-profile.md)：当前重点、不可忽略的责任、时间预算、已有能力、能承受的试验成本、表达偏好。只使用用户提供的信息；变化时改当前项即可。
